# REQ-007 — Embedder

**Phase:** 2 · **Pipeline:** compressed (story → developer → reviewer, no LLD gate) · **GitHub issue:** #<open one>

## Goal
Turn the Chunker's output into vectors, so a user's question and a relevant chunk land as
nearby points in the same space. Two adapters ship: hosted Azure OpenAI for production, and
a local CPU-only adapter so anyone can run the full pipeline with zero cloud credentials.

## In scope

### The Embedder orchestrator
- `Embedder.embed(envelope, chunks) -> list[EmbeddedChunk]`
- Owns the ledger transition: `embedding → indexing` on success; `embedding → embedding`
  (self-transition, TRANSIENT) on retryable failure; `embedding → failed` on PERMANENT failure
- All ledger writes route through `is_benign_concurrent_loss` triage (per REQ-006's pattern
  and issue #9's lesson — do not reproduce the Analyzer gap)
- Batches chunks per adapter's declared `max_batch_size`

### The EmbeddedChunk model
- `EmbeddedChunk`: wraps the `Chunk` from REQ-006 plus:
  - `vector: list[float]`
  - `embedding_model: str` — provenance, e.g. `"text-embedding-3-large"`
  - `embedding_dimensions: int` — post-truncation dimension count
  - `truncated_from: int | None` — original dimension count if MRL truncation was applied
- Frozen pydantic model

### The EmbedderAdapter interface
- Abstract base with:
  - `embed_batch(texts: list[str]) -> list[list[float]]`
  - Properties: `model_name: str`, `native_dimensions: int`, `max_batch_size: int`,
    `max_input_tokens: int`, `supports_mrl: bool`, `document_prefix: str | None`
- Adapters declare their capabilities; the orchestrator respects them

### Matryoshka dimension truncation
- `EmbedderConfig.target_dimensions: int | None` — when set and the adapter reports
  `supports_mrl=True`, truncate each vector to the first N dimensions
- **Re-normalize after truncation** (L2 normalize) — required for cosine similarity to remain valid
- When `target_dimensions` is set but adapter reports `supports_mrl=False`, raise
  `EMBEDDER_MRL_UNSUPPORTED` (PERMANENT) at construction time, not at embed time — fail fast
- Every `EmbeddedChunk` records `embedding_dimensions` and `truncated_from` so downstream
  indexers and future reprocessing know exactly what they're looking at

### Task-type prefixes
- Adapters that require a document-side prefix declare it via `document_prefix`
  (e.g. `"search_document: "` for nomic models; `None` for OpenAI models)
- The orchestrator prepends the prefix to each chunk's text before calling `embed_batch`
- `EmbedderConfig` records the prefix scheme so the query side (out of scope for this REQ)
  can apply the matching query-side prefix
- Document this clearly: a mismatched prefix scheme between ingest and query silently
  degrades retrieval with no error

### Two adapters
- **`AzureOpenAIEmbedder`** — production path. Wraps Azure OpenAI embeddings.
  Default model `text-embedding-3-large` (3072 native, MRL-capable).
  `max_batch_size=96`, `document_prefix=None`.
  Credentials from env only (`AZURE_OPENAI_ENDPOINT`, `AZURE_OPENAI_API_KEY`).
- **`FastEmbedEmbedder`** — local, credentials-free path. Wraps `fastembed`
  (ONNX-based, no PyTorch). Default model `nomic-embed-text-v1.5`
  (768 native, MRL-capable, ~274MB, CPU-only).
  `max_batch_size=32`, `document_prefix="search_document: "`.
  Installed via optional extra: `pip install vestibule[local]`.

### Configuration
- `embedder.yaml`:
  - `adapter: azure_openai | fastembed`
  - `model: text-embedding-3-large`
  - `target_dimensions: 1024` — MRL truncation target; null to keep native
  - `batch_size: null` — null means use the adapter's `max_batch_size`
  - `retry.max_attempts: 5`, `retry.backoff_base_seconds: 2`, `retry.backoff_max_seconds: 60`
- Secrets from env only, never in yaml

### Failure classification (register on module import)
- `EMBEDDER_EMPTY_CHUNKS` — PERMANENT (chunker returned zero chunks)
- `EMBEDDER_MRL_UNSUPPORTED` — PERMANENT (config requests truncation, adapter can't do it)
- `EMBEDDER_INPUT_TOO_LONG` — PERMANENT (a chunk exceeds the adapter's `max_input_tokens`;
  indicates a chunker/embedder config mismatch, not a transient condition)
- `EMBEDDER_RATE_LIMITED` — TRANSIENT (429 from provider; respect `Retry-After` when present)
- `EMBEDDER_UPSTREAM_ERROR` — TRANSIENT (5xx from provider)
- `EMBEDDER_TIMEOUT` — TRANSIENT
- `EMBEDDER_INTERNAL` — TRANSIENT (unclassified; logs original)
- Add all codes to `config/errors.yaml` known_codes and add `ingestion.embedder.model` to
  `ingestion/errors/test_registry.py`'s hand-import list — same PR

### Retries
- In-adapter retry via `tenacity`: exponential backoff + jitter + max attempts, respecting
  `Retry-After` headers on 429s
- Exhausted retries raise the TRANSIENT code; the ledger self-transitions and the caller
  (queue coordinator, out of scope) redelivers

### Tests
- Unit: batching respects `max_batch_size`; a 200-chunk input produces the right number of calls
- Unit: MRL truncation produces vectors of exactly `target_dimensions` length and they are
  L2-normalized (norm ≈ 1.0 within float tolerance)
- Unit: `target_dimensions` set with a non-MRL adapter raises `EMBEDDER_MRL_UNSUPPORTED` at
  construction
- Unit: `document_prefix` is prepended exactly once per chunk when the adapter declares one,
  and not at all when it declares `None`
