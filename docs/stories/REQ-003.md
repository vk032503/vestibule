# REQ-003 — State Ledger

**Phase:** 1 · **Pipeline:** full · **GitHub issue:** #3

## Goal
Provide the persistent state store that records every document's journey through the pipeline.
Every document has exactly one ledger row keyed by `doc_id` (from REQ-002); every stage
transition (analyzing, chunking, embedding, indexing, indexed, failed) is recorded with
attempts, error_code, and updated_at. This is Contract #3 — the framework's memory and the
answer to every operational question ("did doc X make it in?", "why did it fail?").

## In scope
- `LedgerRow` pydantic model: doc_id (PK), status (enum), stage (enum), attempts,
  last_error_code, last_error_message, config_version, ingested_at, updated_at
- `Status` enum: pending | analyzing | chunking | embedding | indexing | indexed | failed
- `LedgerStore` abstract interface with methods:
  - `create(doc_id, envelope_summary) -> LedgerRow` (idempotent — creating an existing row is a no-op returning the existing row)
  - `transition(doc_id, to_status, stage, error_code=None, error_message=None) -> LedgerRow`
  - `get(doc_id) -> LedgerRow | None`
  - `list_by_status(status, limit=100) -> list[LedgerRow]`
- **In-memory implementation** (`InMemoryLedgerStore`) for tests and local dev — fully functional, thread-safe
- `LedgerTransitionInvalid` error class (PERMANENT) for illegal transitions (e.g., indexed → analyzing)
- Legal transition table enforced by the store, not left to callers
- Unit tests: create idempotency, valid/invalid transitions, concurrent updates, list filtering
- Property-based tests: any sequence of legal transitions ends in a consistent state

## Out of scope
- Azure Table Storage / Cosmos DB implementations (Phase 2 — adapters, not the interface)
- Cross-document queries or reporting (a later "operator dashboard" concern)
- The queue / trigger integration (that's the Analyzer's job, later)
- Retention / tombstoning (later — REQ related to compliance deletion)

## Acceptance criteria
1. `create` with the same doc_id twice returns the same row on both calls; second call does not overwrite `ingested_at`.
2. `transition` enforces the legal transition table; illegal transitions raise `LedgerTransitionInvalid` classified PERMANENT.
3. `transition` to `failed` requires `error_code`; missing error_code raises `LedgerTransitionInvalid`.
4. `attempts` counter increments on every retry within the same stage.
5. `updated_at` is set to now() on every transition; `ingested_at` is set only by `create`.
6. `InMemoryLedgerStore` is thread-safe — property test with concurrent transitions produces a consistent final state.
7. `list_by_status` returns rows in updated_at descending order, respects the limit.
8. `get` for an unknown doc_id returns `None`, does not raise.

## Contract touchpoints
- Arrival Envelope: `create()` is called by the arrival adapter using the envelope's `doc_id`
- Idempotency: `create()` is idempotent — safe under at-least-once queue delivery
- **State Ledger: this IS Contract #3**
- Failure Taxonomy: `LedgerTransitionInvalid` = PERMANENT; transitions to `failed` require a classified error_code

## Budget
- p95 latency: < 5ms per transition (in-memory)
- Cost per document: zero (in-memory implementation has no external cost)
