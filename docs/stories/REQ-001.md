# REQ-001 — Arrival Envelope

**Phase:** 1 · **Pipeline:** full · **GitHub issue:** #1

## Goal
Define the single normalized envelope every document must enter the pipeline through,
with validation, so no downstream component ever handles raw source-specific formats.
This is Contract #1; every other component depends on it.

## In scope
- Pydantic model: doc_id, source, blob_path, vertical (optional), scenario_id (optional),
  allowed_groups (list, default empty => deny), trust_tier (enum), content_hash, received_at
- doc_id derivation helper: sha256(source + blob_path)
- Validation: reject missing/invalid fields with PERMANENT error codes
- Serialization to/from queue message JSON
- Unit tests: valid envelope, each invalid-field case, id determinism, round-trip serialization

## Out of scope
- Source adapters that PRODUCE envelopes (Phase 2)
- Queue infrastructure itself

## Acceptance criteria
1. Same (source, blob_path) always yields the same doc_id.
2. Envelope with no allowed_groups deserializes to default-deny (empty list), never org-wide.
3. Invalid envelope raises ENVELOPE_INVALID classified PERMANENT.
4. Round-trip: envelope → JSON → envelope is lossless.
5. Unknown extra fields are rejected (strict schema), with a clear error message.

## Contract touchpoints
- Arrival Envelope: produces the canonical definition
- Idempotency: doc_id derivation lives here
- Ledger: n/a (no state transitions owned)
- Failure taxonomy: ENVELOPE_INVALID = PERMANENT

## Budget
- p95 latency: < 5ms per envelope (pure validation)
- Cost per document: zero (no external calls)
