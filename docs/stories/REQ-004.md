# REQ-004 — Failure Taxonomy

**Phase:** 1 · **Pipeline:** full · **GitHub issue:** #4

## Goal
Provide the classification system that labels every error in the framework as PERMANENT
(never retry, mark failed) or TRANSIENT (retry with backoff, eventually poison). This is
Contract #4 — the framework's decision layer for "what do we do when something goes wrong?"
The retry *execution* is a caller concern; this contract owns the *classification*.

## In scope
- `Severity` enum: PERMANENT | TRANSIENT
- `ErrorCode` value class: code (str), severity (Severity), description (str)
- `ErrorRegistry` — a registry every module registers its error codes into at import time
- `register_error(code: str, severity: Severity, description: str) -> ErrorCode`
- `classify(code: str) -> Severity` — lookup; unknown codes default to TRANSIENT with a logged warning
- `all_codes() -> list[ErrorCode]` — for observability/docs
- `RaggedError` base exception class carrying `error_code: str`; all framework errors inherit from it
- Register the known codes so far: ENVELOPE_INVALID (PERMANENT), IDENTITY_INVALID (PERMANENT),
  LEDGER_TRANSITION_INVALID (PERMANENT)
- Unit tests: registration, lookup, unknown-code fallback, duplicate registration rejection,
  RaggedError carries error_code correctly

## Out of scope
- Retry execution / backoff engine (callers use `tenacity` with our classifier)
- Poison queue integration (Phase 2, queue-adapter work)
- Circuit breakers (later)
- Per-code retry policies beyond the binary PERMANENT/TRANSIENT split

## Acceptance criteria
1. `register_error("ENVELOPE_INVALID", Severity.PERMANENT, "...")` succeeds and can be looked up.
2. Duplicate registration of the same code raises `RaggedError` classified PERMANENT (registry is immutable after first registration).
3. `classify("UNKNOWN_CODE")` returns `Severity.TRANSIENT` and logs a warning naming the unknown code.
4. `classify("ENVELOPE_INVALID")` returns `Severity.PERMANENT`.
5. Existing errors from REQ-001, REQ-002, REQ-003 inherit from `RaggedError` and carry their error_code.
6. `all_codes()` returns every registered code with its severity and description.
7. The registry is thread-safe — concurrent registrations from different modules at import time never lose or corrupt entries.

## Contract touchpoints
- Arrival Envelope: `ENVELOPE_INVALID` registered as PERMANENT
- Identity & Idempotency: `IDENTITY_INVALID` registered as PERMANENT
- State Ledger: `LEDGER_TRANSITION_INVALID` registered as PERMANENT
- **Failure Taxonomy: this IS Contract #4**

## Budget
- p95 latency: < 1ms per `classify` call (dict lookup)
- Cost per document: zero (pure in-memory registry)

## Migration note
REQ-001, REQ-002, REQ-003 currently raise their own error classes. Part of this REQ is
making those classes inherit from `RaggedError` and registering their codes on module import.
This is a non-breaking change: the concrete classes stay, they just gain a base class and
their codes appear in the registry.
